# Direct GPT set coaching

LiftPod calls OpenAI directly from the iPhone. No PC or relay is required.

## Setup

Open **Workout setup → AI coach**, enter your OpenAI API key, tap **Save API key on this iPhone**, and enable AI coaching. The model field accepts a Structured Outputs-compatible model; the default is `gpt-4.1`. Existing model selections, including `gpt-5.6-luna`, are preserved.

The key is stored in the device Keychain, not source files, UserDefaults or workout archives. Clear the field and save to remove it. Client-held keys are appropriate here for personal/testing use; a public app should use individual user keys or a backend.

## Compact input

Each completed set sends only:

- Exercise, training goal, load, target rep range, target RIR and equipment increment.
- An ordered array containing each rep's mean speed, peak speed, duration and speed quality.
- Overall speed degradation, the speed measurement definition, signal usability and interruption status.
- User-confirmed load, reps and RIR when available.

Speeds are rounded to 0.001 m/s, durations to 0.01 seconds, and speed loss to 0.1 percentage points. Missing or invalid speeds are omitted rather than represented as zero. Generic-mode speed covers the whole rep; exercise-profile speed covers the lifting phase. This distinction is included in the request.

Raw acceleration, gyroscope samples, gravity/orientation data, detector transactions, long IDs and absolute sensor timestamps are not sent. Original recordings stay on-device. The app's equation-based RIR is not sent; GPT returns its own provisional estimate from the compact evidence.

For the saved ten-rep diagnostic set, an offline comparison reduced the complete request from about **329 KB to 3.8 KB (98.8% smaller)**. The former full-stream request exceeded the account's 60,000 tokens-per-minute allowance; compact input removes that large numeric stream. Other API quota/rate limits can still apply.

## Output

The end-of-set screen shows GPT-estimated completed-set RIR, concise coaching notes, and a suggested next-set weight, reps and target RIR. Recommendations automatically prefill all three editable next-set targets. RIR is unavailable when the model cannot assess it; the equation estimate is never substituted in that field. Existing live coaching and history review remain separate.

Observations can identify rep-to-rep slowdown or uneven pacing. The prompt explicitly prohibits claims about within-rep sticking points, joint angles, form errors or anatomical weakness from these summaries.

```json
{
  "estimatedRIR": 2,
  "notes": "Provisional estimate and a brief explanation of the next-set suggestion.",
  "weakPoints": [{"rep": 8, "observation": "This rep was slower than the opening reps.", "cue": "Keep the next set controlled."}],
  "nextSet": {"loadLB": 25, "reps": 10, "targetRIR": 2}
}
```

The Responses API request uses `text.format.type = json_schema`, `strict = true`, and `store = false`. The output ceiling is 8,000 tokens, including model reasoning. `store = false` disables response storage, not all API data retention.

The schema permits the existing load, increases up to 10 lb in equipment increments, or a one-step decrease, reps to the target range, next-set RIR to 0–4, and observations to recorded rep numbers. Completed-set estimated RIR is nullable (otherwise 0–10); nextSet is required for completed nonempty sets; observations may be empty. Invalid optional findings are omitted with a notice while valid RIR and notes remain available. Refusal, incomplete output, malformed JSON, insufficient quota and oversized rate-limit requests have distinct errors.

Successful advice is saved in the set summary and workout archive. Delayed responses for previous sets are ignored. Reviewing the latest set invalidates old advice; analyze again to include the correction.

## Verification

`AIWorkoutCoachTests` covers compact-only input, metric rounding, unavailable speeds, strict schema, response parsing, partial validation, error handling and archive compatibility. `WorkoutCaptureRoutingTests` verifies recording-to-summary mapping, saved GPT RIR and applying next-set targets. These are offline tests with no API calls.

- [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text)
- [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)

Recommended rest is generated by GPT in a separate `rest` response object (`seconds`, `reason`). The end-of-set rest card displays it alongside elapsed rest; it does not substitute an algorithmic recommendation when AI rest is unavailable. Older saved advice without `rest` still loads.

## Research context for rest and rhythm

The request appends a compact `trainingContext` block to its instructions. It distinguishes published findings from practical app starting points; it does not send full papers or expand the sensor payload. Reviewed September 12, 2026.

- [Singer et al., 2024 — systematic review and Bayesian meta-analysis](https://www.frontiersin.org/journals/sports-and-active-living/articles/10.3389/fspor.2024.1429789/full): nine studies suggested a small hypertrophy benefit above 60 seconds, with uncertainty and no appreciable additional difference detected beyond 90 seconds. This does not establish a universal optimal rest duration.
- [Schoenfeld et al., 2016 — randomized trial](https://pubmed.ncbi.nlm.nih.gov/26605807/): 21 trained young men, eight weeks; three-minute rests outperformed one-minute rests for squat/bench strength and anterior-thigh thickness, with a trend for triceps thickness. It did not test 90 seconds and should not be generalized to every exercise or person.
- [Grgic et al., 2018 — strength systematic review](https://pubmed.ncbi.nlm.nih.gov/28933024/): 23 studies, 491 participants; longer than two minutes appeared beneficial for maximizing strength in trained lifters, while 60–120 seconds could suffice in untrained lifters. Training experience is not currently supplied, so the model must not assume it.
- [Schoenfeld, Ogborn & Krieger, 2015 — repetition-duration meta-analysis](https://pubmed.ncbi.nlm.nih.gov/25601394/): similar hypertrophy across total rep durations of 0.5–8 seconds in the included failure-training studies. This supports flexibility, not prescribing that range or claiming all tempos are equivalent for strength. Whole-rep timings cannot identify concentric/eccentric tempo separately.

**Application choices, not experimentally proven optima:** use 120–180 seconds as a starting point for hypertrophy working sets, 180–300 for heavy strength/compound work, and allow 90–120 for easier isolation work. Favor longer rest for demanding sets or preserving next-set performance; explain shorter choices. These ranges guide the LLM, not a deterministic timer or new schema floor. A 90-second suggestion remains possible when justified. Users can always start before the recommendation. No recovery time is calculated from speed loss alone.

## RIR evidence context

The same compact instruction block defines RIR as additional complete reps possible at the same load and technique before failure and explains how to use the measurements actually supplied. It asks the model to compare late usable mean speeds with consistent opening reps, look for sustained trends, corroborate with durations, and avoid a single slow outlier. This is a qualitative estimation procedure, **not a validated calculation of RIR for this device**. There is no newly added formula, personal calibration, or additional sensor payload.

- [Jukic et al., 2024, Physiological Reports](https://doi.org/10.14814/phy2.15955): 46 trained participants completed squat tests to failure. Individual RIR–velocity relationships predicted a subsequent session better than general relationships, with mean errors under two reps in the reported individual models. Those calibrated exercise-specific findings do not establish accuracy for an uncalibrated wearable or a different exercise.
- [Paulsen et al., 2025, PeerJ](https://pubmed.ncbi.nlm.nih.gov/40832580/): 19 trained participants performed squat/bench sessions over six weeks. Relationships between velocity and perceived RIR varied with exercise, load, velocity-loss threshold and set. Perceived RIR and bar velocity were complementary, not interchangeable; this study did not measure actual remaining reps to failure at every observation.

Application boundaries: no universal speed-loss percentage or absolute failure speed, no extrapolation to zero velocity, no conversion of prescribed target reps/RIR into achieved RIR. Whole-rep and lifting-phase speeds are distinguished; peak speed is not substituted for mean velocity. Tempo, pauses and range changes may affect speed. Confirmed user RIR is a self-report anchor when supplied. Completed nonempty sets receive a best-estimate integer RIR without confidence metadata. The prompt does not repeat technical limitations in workout notes unless they affect an actionable suggestion.

## Authoritative rep counts and note tone

Each request explicitly sends `completedReps` and `repCountSource`. A user-confirmed count overrides the detected measurement-array length; missing speed never subtracts a rep. Measurements are retained without inventing samples for manually added reps. When confirmed and measured counts differ, numbered rep observations are disabled because their correspondence cannot be assumed. The post-set count and target assessment follow the logged total, and confirming a set triggers a fresh analysis when coaching is enabled.

Notes, rest reasons and cues focus on the workout and next action. The prompt forbids commentary about difficulty estimating effort, sensor quality or calibration in those text fields; estimates are supplied directly without confidence metadata. Notes do not restate the rep total already displayed by the app. Prompt instructions reduce these errors but are not a guarantee about free-text model output.

## Measured speed degradation and next-set availability

Live and completed-set speed degradation now compares the opening and closing available mean speeds (mean of up to two values per window; at least three valid rep speeds; faster endings display 0%). It is a descriptive trend across measured reps, independent of the stricter calibrated RIR profile. Missing samples are skipped, never treated as zero, and only matching estimator versions/measurement kinds/learning epochs are compared. The UI labels it “Measured reps” and explains when too few speeds exist. The RIR calibration pipeline is unchanged.

For a completed nonempty set with known weight, the response schema requires a next-set object rather than allowing null. The prompt permits maintaining weight and selecting a rep target when effort is uncertain. Missing weight uses the user-requested 10 lb starting point. This applies to new analyses; old saved responses can still have no next-set suggestion.

## No coaching confidence output

The coach no longer returns, validates, saves or displays a confidence field. Completed nonempty sets require an integer RIR estimate (0–10) in the response schema; lack of personal calibration does not suppress it. Empty/interrupted sets may return null. Existing archives containing the old confidence field still decode, ignoring that field. Notes and recommendations must not hedge about estimation difficulty. Numerical and measurement-validity checks remain to prevent malformed output or invented sensor readings, not to score confidence.

## Editable next-set prefill

Coach weight/reps/target RIR now populate the next-set fields when analysis completes; Coach Notes no longer contains a separate recommendation card or apply button. The prompt places numerical next-set targets only in `nextSet`. The helper reads “Set next set's weight and rep goal. Recommended values pre-filled.” Users can edit the fields, and changes made while analysis is pending are preserved instead of overwritten by a late response.

New selections and cleared weight fields start at 10 lb. Existing logged history is not rewritten. The API receives `recommendationBaseLoadLB`: entered/confirmed weight, or the explicit 10 lb assumption when absent, so the same equipment-step rules can still produce a next-set recommendation.

For easy sets substantially above the rep target, the prompt asks the coach to consider the full 10 lb increase instead of defaulting to 5 lb. The model still chooses the recommendation; 10 → 20 lb is allowed, not forced. Schema and validation share the same allowed-weight list.
